# GenAI

This directory contains notes and implementations covering the core concepts required to understand Generative AI applications and modern LLM-based systems.

The focus is on understanding how LLM applications work, how information can be retrieved and supplied to models, how tools can be integrated, and how agentic workflows can be designed and evaluated.

---

## Topics

### Prompt Engineering

Prompt Engineering focuses on designing instructions that help language models produce useful, reliable, and appropriately structured outputs.

Topics include:

- Clear instructions
- Context
- Output requirements
- Constraints
- Examples
- Prompt refinement
- Prompt evaluation

---

### Prompt Chaining

Prompt chaining breaks a larger task into multiple model calls where the output of one step becomes the input to another.

A simple conceptual flow is:

```text
Input
  |
  v
Prompt 1
  |
  v
LLM
  |
  v
Output 1
  |
  v
Prompt 2
  |
  v
LLM
  |
  v
Final output
```

Prompt chaining can make complex workflows easier to reason about and can separate distinct tasks into smaller steps.

---

### Prompt Templates

Prompt templates allow a reusable prompt structure to be combined with dynamic input.

A simple example:

```python
template = """
Summarize the following text in {format}:

{text}
"""

prompt = template.format(
    format="three bullet points",
    text=document,
)
```

Templates are useful when the same instruction needs to be applied repeatedly to different inputs.

### Tokens & Tokenization

A tokenizer converts input text into tokens that can be processed by a language model.

A token is not necessarily a word. Depending on the tokenizer, a token may represent part of a word, a complete word, punctuation, whitespace, or another text fragment.

A simplified processing flow is:

```text
User prompt
    |
    v
Tokenizer
    |
    v
Tokens
    |
    v
Language model
    |
    v
Generated tokens
    |
    v
Decoded response
```

Tokenization matters because model context windows and many model APIs measure input and output in tokens.

Token counts can also affect:

- Context-window usage
- Latency
- Cost
- Prompt design

Tokenization is model/tokenizer dependent, so an illustrative tokenization example should not be treated as universal.

### Embeddings

Embeddings represent text or other data as numerical vectors.

They are commonly used for:

- Semantic search
- Similarity comparison
- Retrieval-Augmented Generation (RAG)
- Clustering
- Recommendation systems

A simplified representation is:

```text
Text
  |
  v
Embedding model
  |
  v
Vector
  |
  v
Vector database / similarity search
```

Two semantically similar pieces of text can have vectors that are close to each other according to a chosen similarity or distance metric.

A common similarity measure is cosine similarity:

```text
cos(θ) = (A · B) / (||A|| × ||B||)
```

Embeddings used for retrieval are generated by an embedding model. They should not be treated as identical to the internal representations used by a generative language model.

---

### Vector Databases

Vector databases store and retrieve high-dimensional vectors efficiently.

They are commonly used when an application needs semantic retrieval over documents or other embedded data.

A typical flow is:

```text
Document
   |
   v
Chunking
   |
   v
Embedding model
   |
   v
Vector
   |
   v
Vector database
```

At query time:

```text
User query
   |
   v
Query embedding
   |
   v
Vector similarity search
   |
   v
Relevant results
```

Common concepts include:

- Vector embeddings
- Similarity search
- Metadata filtering
- Approximate nearest-neighbor search
- Indexes
- Distance metrics

---

### Retrieval-Augmented Generation (RAG)

RAG combines retrieval with generation.

Instead of relying only on the model's learned parameters, the application retrieves relevant external information and provides that information to the model as context.

A typical RAG system has two related flows.

#### Indexing flow

```text
Documents
    |
    v
Chunking
    |
    v
Embedding model
    |
    v
Vectors + metadata
    |
    v
Vector database
```

#### Query flow

```text
User query
    |
    v
Query embedding
    |
    v
Retriever
    |
    v
Relevant documents
    |
    v
Prompt + retrieved context
    |
    v
LLM
    |
    v
Answer
```

RAG systems can use different retrieval strategies, including:

- Dense/vector retrieval
- Keyword retrieval
- Hybrid retrieval
- Metadata filtering
- Reranking

The retrieved context is then supplied to the language model so that the generated answer can use the retrieved information.

---

### RAG Evaluation

RAG evaluation focuses on measuring both retrieval quality and generated-answer quality.

Important dimensions include:

- Retrieval relevance
- Context relevance
- Context completeness
- Faithfulness to retrieved context
- Answer relevance
- Answer correctness

Evaluation should distinguish between problems caused by retrieval and problems caused by generation.

For example:

```text
Question
   |
   v
Retriever
   |
   +----> Poor retrieval
   |          |
   |          v
   |      Bad context
   |
   v
Relevant context
   |
   v
LLM
   |
   +----> Poor generation
              |
              v
          Poor answer
```

### Tool Integration

Tool integration allows an LLM-based application to invoke external functions or services when additional capabilities or information are required.

A typical tool-calling flow is:

```text
User
  |
  v
LLM
  |
  v
Tool decision
  |
  v
Tool call
  |
  v
Tool execution
  |
  v
Tool result
  |
  v
LLM
  |
  v
Final response
```

Tools can provide capabilities such as:

- Database queries
- API calls
- Search
- Calculations
- Application-specific operations

Tool definitions should clearly describe:

- Tool name
- Purpose
- Input parameters
- Parameter types
- Required parameters
- Expected result

External tool execution should be validated and controlled by the application rather than blindly trusting model-generated arguments.

### LangChain

LangChain provides abstractions for building applications around language models.

Topics include:

- Models
- Prompts
- Prompt templates
- Chains
- Retrievers
- Tool integration
- Basic composition

LangChain can help connect multiple application components into a workflow, but it does not replace the need to understand the underlying LLM, retrieval, API, and application concepts.

### AI Agents

An AI agent is an application pattern in which a model can determine what action to take, invoke available tools, observe their results, and continue until it can produce a final response or reaches a defined stopping condition.

A simplified agent loop is:

```text
User input
    |
    v
LLM
    |
    v
Decide next action
    |
    +----> Final answer
    |
    +----> Tool call
              |
              v
         Tool execution
              |
              v
          Tool result
              |
              v
             LLM
```

Agent systems commonly need controls such as:

- Maximum iterations
- Tool validation
- Input validation
- Output validation
- Timeouts
- Error handling
- Permission checks
- Guardrails

A simple iteration limit can prevent an agent from continuing indefinitely:

```python
MAX_ITERATIONS = 10

for _ in range(MAX_ITERATIONS):
    ...
```

Agents should be treated as application workflows with explicit boundaries rather than as unrestricted autonomous systems.

## Learning Approach

For each GenAI topic:

1. Understand the underlying concept.
2. Study a minimal implementation.
3. Identify where the concept fits in a real backend application.
4. Consider reliability, evaluation, security, and operational concerns.
5. Apply the concept to practical projects where appropriate.

The goal is to understand both the model-facing concepts and the backend engineering required to build reliable LLM-powered applications.
