## Repair protocol

1. Choose only problems marked incorrect, slow, or hint-assisted on Day 87.
2. Re-solve without looking at prior code.
3. State the brute-force approach before optimizing.
4. Write the invariant or recurrence before implementation.
5. Test empty input, smallest valid input, duplicates, disconnected components, and impossible states as relevant.
6. Record time complexity and auxiliary space separately.
7. Reattempt missed problems tomorrow before checking solutions.
