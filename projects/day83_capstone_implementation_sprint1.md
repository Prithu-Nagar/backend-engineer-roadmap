# Day 83 — Capstone Implementation Sprint 1

## Sprint objective

Turn the Day 81 requirements and Day 82 database/API contracts into a small,
testable implementation increment. Keep existing application behavior intact;
do not describe planned capabilities as implemented until they pass tests.

## Sprint scope

1. Implement a framework-independent task service boundary.
2. Validate task input and allowlist mutable fields.
3. Define predictable not-found and validation failures.
4. Add deterministic unit tests for valid, invalid, and missing-resource cases.
5. Connect the service to the existing persistence layer in a follow-up step
   after confirming the repository's actual model and transaction setup.

## Implementation artifact

The accompanying `task_service.py` provides a small in-memory service contract
for isolated development and tests. It is not a production persistence adapter.
Replace the in-memory store with the project's repository/ORM implementation
without moving validation rules into route handlers.

## Acceptance criteria

- [ ] Invalid titles and unsupported fields are rejected.
- [ ] IDs are generated by the service and are stable for the lifetime of a record.
- [ ] Updates modify only explicitly allowed fields.
- [ ] Missing IDs raise a predictable domain exception.
- [ ] Tests cover create, read, update, validation failure, and not-found behavior.
- [ ] No credentials or sensitive payloads are logged.
- [ ] API routes map domain exceptions to documented HTTP responses.
- [ ] Database persistence and transaction behavior are verified before production claims.

## Next sprint

Integrate the service with the actual database model/repository, add transaction
tests and API contract tests, then run the complete test suite and quality checks.
